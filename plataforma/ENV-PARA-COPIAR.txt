PORQUE NÃO É PRECISA A CHAVE service_role
-----------------------------------------
A versão inicial usava a chave service_role para criar o perfil do
utilizador no registo. Foi substituída por um gatilho na base de dados
(`on_auth_user_created`), que é melhor por três razões:

  · ATÓMICO   — corre na mesma transação que cria a conta de autenticação,
                por isso é impossível ficar com contas sem perfil
  · SEGURO    — a aplicação deixa de precisar de uma chave que ignora
                todas as regras de segurança da base de dados
  · SIMPLES   — sem código de reversão manual em caso de falha

A chave service_role continua a existir no painel do Supabase, mas não
pertence a este projeto. Só será necessária no futuro para tarefas
administrativas em lote (motor de correspondência agendado, por exemplo).

  SET role = 'PLATFORM_ADMIN', verification = 'APPROVED'
  WHERE email = 'o-seu-email@exemplo.com';
